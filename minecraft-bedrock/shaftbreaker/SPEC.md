# The Shaftbreaker — Minecraft Bedrock add-on design spec

Single source of truth for everyone building this add-on (model, texture,
animations, packs). **Minecraft Bedrock Edition only.** Nothing in this folder
touches the CubicWorld game in the repository root.

Reference art: `tools/reference/concept_art.jpg` (five phases) plus zoomed crops
in `tools/reference/*.png` (`dormant_full`, `dormant_head`, `dormant_torso`,
`dormant_hands`, `dormant_feet`, `stalk_full`, `watch_full`, `breaker_full`,
`frenzy_full`, `frenzy_head`). The goal is a model and animations that match
that art as closely as Bedrock geometry allows: head, face, mane, body,
limbs, hands, feet, texture and the five phase poses.

## 2. Coordinate & rotation conventions (CRITICAL — verified against vanilla rigs)

Bedrock **file** coordinates (what you write in .geo.json / animations):
* +Y is up, ground is y = 0, the creature stands at the origin.
* The creature FACES **-Z** (its front/face is on the -Z side; "north" cube faces are its front).
* The creature's **RIGHT** side is **-X**, its **LEFT** side is **+X** (same as vanilla: `rightArm` pivot is at x = -5).
* Units: 1 unit = 1/16 block **before** the client-side render scale (see §3).

Rotation signs (degrees, Bedrock file convention, applied Z·Y·X like vanilla/Blockbench):
* **+X rotation pitches a bone FORWARD**: a bone pointing UP (spine, neck, head) tips its top toward the front
  (hunch / look down). A bone hanging DOWN (arm, leg, finger) swings its lower end **BACKWARD**.
  * hip flexion (thigh forward)          = **negative X**
  * knee flexion (shin folds back)       = **positive X**   (a knee may NEVER go below 0°)
  * ankle: toes down = positive X, toes up = negative X
  * shoulder flexion (arm raised forward) = **negative X**
  * elbow flexion (forearm folds forward) = **negative X**  (an elbow may NEVER go above 0°)
  * finger curl (toward the palm, palm faces FRONT) = **negative X** (no hyper-extension past +15°)
  * jaw open (front of jaw drops)        = **positive X**
  * torso hunch forward / head look down = **positive X**
* **Z rotation**: for the RIGHT arm/leg (at -X) **+Z swings it outward** (abduction);
  for the LEFT arm/leg (at +X) **-Z swings it outward**. For the spine, +Z leans the top toward the creature's LEFT.
* **Y rotation**: +Y turns a bone's front (−Z side) toward the creature's RIGHT (−X); −Y turns it toward its LEFT.
* Animation rotations are ADDED (Euler) to the bone's rest rotation. Animation positions are offsets in the
  parent's space; position X is in file convention (−X = creature's right).
* Always verify with renders. In `--debug-bones` the red axis is +X in RENDER space = the creature's RIGHT.

## 3. Scale & bounds

* The geometry is authored at **art scale**: head 8 units wide, standing height ~84 units.
* Client entity applies `"scripts": { "scale": "0.58" }` → ~3.0 blocks tall in game (Warden ≈ 2.9).
  The renderer uses the same 0.58 scale. Collision box is set in the BP (width 0.9, height 2.9).
* Geometry `visible_bounds_width` 6, `visible_bounds_height` 7, `visible_bounds_offset` [0, 3, 0].
* Texture density: `texture_width`/`texture_height` declared in the geo = **model units** (1 declared texel per unit);
  the PNG is **4× the declared size** (4 real texels per unit, HD) — Bedrock & Blockbench normalise UVs by the
  declared size, so this is legal and renders in HD. All cube sizes / origins must lie on the 0.25-unit grid
  (= 1 real texel) so every face maps to whole texels. Per-face UV (`"uv": {"north": {"uv": [u,v], "uv_size": [w,h]}}`).

## 5. Look & materials

* Body = stacked small stone "bricks" (each ≈1.25–2 units, i.e. 5–8 real texels) with mortar seams, per-brick tone
  variation, 1-texel bevel (lighter top/left, darker bottom/right), occasional cracks. Granite-like warm
  mauve-taupe. Albedo palette (unlit): base ≈ #96766c, light ≈ #c4a498, dark/mortar ≈ #4a3632,
  soot ≈ #2a201c. Top-facing faces slightly dustier/lighter.
* Silhouette is jagged: limbs are built from a core cube plus small offset "plate" cubes (0.5–1 unit proud)
  so edges look like stacked voxels — never a single smooth box per limb.
* Soot/char: dark vertical streaks on the lower half of the shins and feet, on hands, fingers, forearm near
  the wrist; claws are near-black (#1e1714) with a slightly lighter tip highlight.
* Mane: dense collar of stepped spikes (each 2–3 stacked cubes tapering to a point, 4–8 units long,
  rotated outward), radiating from neck/shoulders: sideways-up on the shoulders, up beside the head
  (reaching ~2/3 of head height), forward-down over the upper chest, up/back on the upper back.
  Front view: collar ~30 units wide. Spikes slightly lighter (#a88a80 lit tops).
* Head: box ≈ 8 w × 8 d × 10.5 h. Face (front, -Z): two square glowing eyes ≈1.5–2 units, centred around
  50 % of head height, inner gap ≈ eye width; below them a cheek band, then a dark mouth band with
  TWO ROWS of FOUR glowing teeth (upper row hangs from the skull, lower row rises from the jaw, thin dark
  gap between rows), then a thin chin. Faint brick seams on the skull. Frenzy opens the jaw wide
  (dark mouth interior + teeth top and bottom, see `frenzy_head.png`).
* Material: `entity_emissive_alpha` — texture ALPHA encodes glow (alpha 0 = full glow, 255 = normal).
  Eyes: warm white core #fff4dc with #ffb05a rim, alpha 0–30. Teeth: #f2e2c8, alpha ≈ 70.
  Everything else alpha 255. Mouth interior near-black #120c0a, alpha 255.

## 6. Behaviour phases (server) and identifiers

* Entity identifier: `shaftbreaker:shaftbreaker`; family `shaftbreaker`, `monster`, `mob`.
* Entity property (client_sync): `shaftbreaker:phase` enum
  `["dormant", "stalking", "watching", "breaker", "frenzy"]`, default `"dormant"`.
* Phase flow (BP decides details; must be robust and only use documented components):
  dormant → (player within ~24 blocks) → stalking → (player looks at it, `minecraft:lookat`) → watching
  → (after a few seconds / player approaches / it is hurt) → frenzy; stalking/frenzy → breaker when the
  path to the target is obstructed or on a timer while underground (uses `minecraft:break_blocks` on
  stone / deepslate / mineshaft blocks; respects mobGriefing); frenzy / breaker → back to stalking or
  dormant when the target is lost. Hurt in any phase → frenzy.
* Spawns underground in total darkness (rare), overworld caves / mineshaft depths.

## 7. Animations (resource pack) — names are FIXED

All rotations obey §2 and the joint limits. Smooth: use `"lerp_mode": "catmullrom"` on EVERY keyframe of a
channel or on none (never mix within a channel). Loops must be seamless (first keyframe == last keyframe).
No bone may pass through another major part (hands through thighs/torso, legs through each other).
Feet must stay on the ground (y≈0) when planted; no floating, no sinking below −0.5 units.

| short name | full name | loop | driven by | description (match the concept art panel) |
|---|---|---|---|---|
| dormant | animation.shaftbreaker.dormant | true (≈8 s) | time | DORMANT panel: upright, perfectly still, arms hanging straight slightly away from the body, claws loosely curled, staring forward. Only uncanny micro-motion: barely-visible breathing, one sudden tiny finger twitch / 2° head jolt every few seconds. |
| look_at | animation.shaftbreaker.look_at | true | additive | head/neck follow `query.target_x_rotation` / `query.target_y_rotation` (clamped, split ~35 % neck / 65 % head). |
| stalk_idle | animation.shaftbreaker.stalk_idle | true | time | STALKING pose held: torso hunched forward ~30°, hips lowered with bent knees, head thrust forward, shoulders up, arms dangling forward with elbows slightly bent and claws curled near knee height; slow breathing, slight sway. |
| stalk_walk | animation.shaftbreaker.stalk_walk | true | `anim_time_update: query.modified_distance_moved` (anim time = blocks moved; `animation_length` = blocks per full stride cycle) | slow, deliberate creeping walk in the stalking pose: high careful leg lifts, long reach, planted feet must not slide (planted foot moves backward exactly `16/0.58` units per block), arms swing slightly with lag, head stays level and locked forward. |
| watch | animation.shaftbreaker.watch | true (≈6 s) | time | WATCHING panel: body turned ~35° away (Y), head/neck turned back toward the front, slight head tilt, weight on one leg, near-upright with a slight hunch, tense twitchy fingers, occasional sharp "on edge" head tilt. |
| breaker_smash | animation.shaftbreaker.breaker_smash | true (≈1.8 s) | time | BREAKER panel: wide low stance, torso pitched forward; alternating brutal claw strikes — one arm raised high then slammed forward/down into the wall, the other ripping low; torso twists with each blow; particle events on impact (`claw_right` / `claw_left`). |
| breaker_walk | animation.shaftbreaker.breaker_walk | true | distance (as stalk_walk) | heavy stomping shove forward, arms clawing ahead alternately, used while moving in breaker phase. |
| frenzy_idle | animation.shaftbreaker.frenzy_idle | true | time | crouched, coiled to pounce, arms spread wide claws open, jaw open, mane flared, rapid breathing. |
| frenzy_run | animation.shaftbreaker.frenzy_run | true | distance | FRENZY panel: full sprint — torso forward 35–50°, long bounding strides with heavy knee drive, arms flung forward/out with claws spread, jaw wide open, mane flared, head forward. |
| frenzy_lunge | animation.shaftbreaker.frenzy_lunge | false | attack (one-shot ~0.9 s) | wind-up crouch, explosive lunge with both claws sweeping in, recover. Triggered by the attack controller. |

Timeline effects available to animations (defined in the client entity — use exactly these names):
* `particle_effects`: `debris` (burst of stone chunks; use with locator `claw_right` / `claw_left` on breaker impacts),
  `step_dust` (small dust puff; locator `foot_right` / `foot_left` on heavy footfalls).
* `sound_effects`: `step` (heavy stone footstep), `smash` (stone-breaking impact), `scrape` (claw scrape),
  `screech` (frenzy roar). Example: `"sound_effects": { "0.42": { "effect": "smash" } }`,
  `"particle_effects": { "0.42": { "effect": "debris", "locator": "claw_right" } }`.

Animation files: `shaftbreaker.dormant.animation.json` (dormant, look_at), `shaftbreaker.stalking.animation.json`,
`shaftbreaker.watching.animation.json`, `shaftbreaker.breaker.animation.json`, `shaftbreaker.frenzy.animation.json`.
Format version `"1.8.0"`. Movement-driven animations: one full cycle (both steps) = `animation_length` blocks.

Client entity wiring (RP): animation controller `controller.animation.shaftbreaker.phase` picks the phase
from `q.property('shaftbreaker:phase')` (blend_transition ≈ 0.4–0.6 s); within moving phases blend idle ↔ walk
with `query.modified_move_speed`; `controller.animation.shaftbreaker.attack` plays `frenzy_lunge` on
`variable.attack_time > 0`; `look_at` is always active with a weight from `pre_animation`
(0 in dormant — it stares straight ahead — 1 elsewhere).
